# Project conventions
- Native helpers in `src/lib/native.ts` handle OAuth and allowlisted item links at root with cleanup/cold starts; close Browser before OAuth session I/O, suppress redirects, use Browser for external documents. HTTPS app association needs real signing identifiers.
- Web downloads share `src/lib/downloads.ts` (Storage attachments, blobs, reserved-tab fallback). Native details use `native-offline.ts`: PDFs and minimal metadata in Filesystem Directory.Data, guarded local reads/removal, one cleaned-up Network listener; the Baixados filter of /biblioteca is native-only. Keep bundled startup without server.url for cold offline launch.
- Repository UI lives in `src/components/repository`; presentation changes never require schema changes.
- Keep academic filtering, author formatting and browser-only reading history in `src/lib/repository.ts` with focused behavior tests; these rules must be reusable and independently verifiable.
- Test files stub platform plugins (Capacitor), not the app's own modules: `mock.module` persists into later test files in one `bun test` run and would blank real exports other suites import.
- Reading history stores only article IDs under a user-scoped browser key, not permissions or snapshots; it is device-local, not synced analytics.
- All routes use RepositoryShell as the sole owner of institutional header/sidebar/footer, so navigation and theme remain identical without page-level chrome.
- Institutional link ordering, mobile account shortcuts and the search tab's destination come from shared navigation definitions; the shell provides bottom navigation below the desktop breakpoint, and on the search route its mobile header row becomes the auto-focused search bar with one clear action.
- RepositoryShell measures the fixed header height for content and full-height sidebar offsets; page wrappers stay fluid to keep routes edge-to-edge, except the privacy page's centered inner desktop grid.
- Collections share RepositoryCollection and memoized PublicationCard with stable ID callbacks to prevent list-wide rerenders.
- Mobile filter chips and the year/author bottom sheet share RepositoryCollection filter state with desktop controls, so changing presentation never changes academic filtering rules.
- The sidebar menu lists only collection and section destinations while institutional identity lives in the sidebar's institutional block, and each article page renders its citation once, so no destination or bibliographic string is offered twice.
- Article citations use only existing metadata; absent DOI, affiliation or translated abstract must never be invented.
- Institutional content lives on one page (`/linhas-de-pesquisa`) covering mission, objectives, research lines and researchers; former addresses (`/sobre`, `/integrantes`) redirect there keeping a known section anchor, so no destination is offered twice.
- Admin forms use FileDropzone/FormSection/FormPageHeader from `src/components/repository/FileDropzone.tsx` so PDF and image uploads share one drag & drop area and section layout.

- Quick category chips derive from shared academic search matches before refinement; the full category selector remains independent of the quick-chip limit, and Tudo clears refinement without discarding search so advanced categories remain selectable.
- The quick-filter chip bar keeps one non-wrapping row via `.repository-chip-scroll` in `src/index.css` (overflow-x auto, scrollbar hidden, touch-action untouched, chips shrink-0), so pills never stack, no scrollbar shows, thumb swipe and vertical page swiping still work, and the advanced-filters icon stays on the same line.
- Admin content cards keep the text column min-w-0, 40x40 shrink-0 icon actions and flex-wrap metadata/tags (gap-1.5), so edit/delete never leave the screen at phone widths; titles text-base leading-snug, secondary metadata text-xs, cards/pages px-4 py-3 with bottom padding clear of the mobile bar.
- Account actions live on one surface each: the admin panel has no "Ver Site"/"Sair" header buttons (shell navigation covers them), while the profile quick actions carry sign-out (`supabase.auth.signOut()` then `/auth`).
- The document viewer offers each opening action once: externally hosted documents keep the header free of "Abrir em nova aba" and open only through the central "Acessar documento", while embedded readers keep that header button.
- Owner-authored policy pages live on app-owned routes (`/privacidade`) linked from the shared footer and state only facts the group provided; the contact is the group's published address, so no invented channel or compliance claim appears.
- Detail pages share one item through `shareContent` in `src/lib/native.ts`, which passes the item title and its canonical public link to the platform sheet (Capacitor on native, `navigator.share` on web) and copies the link when no sheet exists; the helper reports which channel delivered it so the page can confirm a copy, and a sheet the user closed is never treated as a failure.
- Academic items have one canonical address, `/publicacao/{id}` through `publicationPath` in `src/lib/repository.ts`, so cards, citation, sharing and routing never disagree; older `/artigo` and `/article` links redirect there and news keeps its own `/noticia/{id}`.
- Collection read actions link to the canonical detail page, never a modal; DocumentPreview uses the shared file URL helper and PDF.js beneath the abstract for cross-device rendering, while blocked/non-PDF destinations use the integrated-browser helper.
- Detail tabs/actions share a desktop toolbar; mobile tabs scroll independently.

- AuthProvider shares one live Supabase session subscription across routes; never persist permissions.
- Favorites share user-keyed React Query and ID-only local cache with optimistic item rollback; articles share stale-while-revalidate queries so populated lists survive refresh errors.
- `hover:` utilities apply only on pointer devices (custom variant in `tailwind.config.ts`): a touch tap leaves `:hover` stuck and buttons look permanently selected; use `active:`/state props for touch feedback.
